# Exploration notes and source boundary

Impeccable was used in Operate mode. PRODUCT.md, DESIGN.md, the completed critique, route tree, feature modules, coverage documentation, CP6 fixture/oracles and assistant response fixtures informed the work. DESIGN.md was treated as incumbent evidence, not an approved style. No stock imagery, customer logos, medical claims or generated raster assets were needed.

The skill's direction-seed helper made a free GET for reference metadata to `impeccable.style/api/roll`. No application data was uploaded; no hosted inference, image generation or billable request ran. Its direction reference was `seed:0058f9ba8e2d9775`. Generated helper records are isolated in `seed-context/`; the PRODUCT.md there is a context snapshot, not a second product authority. An initial unscoped helper invocation was retained there as provenance and had no effect on application decisions.

The returned reference families were treated critically:

- Reference-manual/acetate organization suggested precise divisions and retrievable source context, expressed in Registre without simulated materials or decoration.
- Mascot/catalog motifs were rejected as inappropriate for this task. Only clear taxonomy and differentiation between similar entries were useful; no mascot was added.
- Metro/typographic tiles offered strong navigation hierarchy, but giant typography/tiles were rejected because they would consume analytical space.
- Additional reference families (grid specimen, wayfinding, data-art) reinforced alignment and grouping. They did not justify decorative technical patterns, invented data or animated spectacle.

The final three *candidates* were developed in parallel as isolated HTML studies, as the skill's new-work procedure directs. They differ by task organization: parallel register, staged workspace, continuous report. They deliberately use comparable fixture content. No scoring system, random seed, automated decision service or recommendation selects a winner; user approval remains the only selection gate.

All prototype assets, scripts, text and CSS are local. Candidate fonts use installed/system fallbacks; no external font package or dependency was added. Palette and layout departures are explicitly authorized proposals; no incumbent DESIGN.md or Impeccable setting was rewritten to treat a proposal as adopted.

After delivery, the requested Stop-hook triage created shared `.impeccable/config.json` through `impeccable hooks ignore-value`. The exceptions are limited to cream-palette for B/C and the intentional Cambria design-system-font mismatch in C. Reasons explicitly distinguish agent-authored comparison studies from user-approved directions. This is detector bookkeeping, not adoption of either proposal; production rules remain active. See REVIEW.md for the triage and verification record.
