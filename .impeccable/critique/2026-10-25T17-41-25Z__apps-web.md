# UI/UX critique — analytics platform and pharmacy assistant

Date: 2026-10-25. Target: `apps/web/`. PRODUCT.md supplies product context; DESIGN.md describes the incumbent, without endorsing it. This report proposes improvements for review and authorizes no implementation.

**The platform's largest weakness is the effort required to obtain and inspect a useful result. The assistant has a clearer task flow, but makes important context too small and hides one mobile validation message.** The first priorities are protecting work, making results readable, and sequencing analytical decisions. No P0 task-wide blocker was established in the inspected states.

## Design specificity and overall impression

**The product logic is more specific than the visual organization.** Immutable versions, original cells, missing-value distinctions, result-only sharing and dated pharmacy facts are useful differentiators. The platform expresses many of them through the same large heading, explanatory paragraph and rounded white-panel pattern. Sources, configuration, results, sharing and destructive actions consequently have similar visual weight. The workspace feels organized around implemented features rather than the user's current question.

The assistant's narrow conversation, explicit presentation choices and recorded-price cards fit its purpose. Its serif/italic welcome heading, uppercase eyebrow and three icon cards are familiar assistant/landing-page conventions. Those similarities do not establish AI authorship. System fonts, familiar native controls and green accents are not defects by themselves; unnecessary sameness between different tasks is the problem.

**Deterministic scan:** one real `impeccable detect --json apps/web/` run returned `[]` and exit 0: zero findings, no rule/file locations or false positives. That limited rule result does not contradict the observed draft loss, cognitive load or chart-readability problems. No detector overlay was injected; starting its live server would conflict with the user's constraint.

## What is working

1. **Trustworthy context exists in the interface:** explicit versions, original cells, missingness/denominators, exact-result tables and medication source dates. Preserve this while shortening the default view.
2. **Important actions have real boundaries:** full-file validation before publication, dependency review before deletion, distinct dataset/result grants, and explicit reset confirmation. Backend safety must survive any interface simplification.
3. **Useful accessibility and recovery foundations:** labeled native fields, keyboard focus outlines, skip links, a polite chat log, chart descriptions/table alternatives, reduced motion, and explicit retry/edit paths. These are assets to retain, not proof that every journey is accessible.

## Prioritized findings

### 1. [P1 — Major] Ordinary navigation silently discards analytical work

**Evidence: current synthetic-render interaction, corroborated by code.** Editing a saved analysis title, clicking header “Mes données,” and returning restored the original title without a dialog. Editing dataset description and switching “Données → Vue d’ensemble” also lost the draft without warning. Analysis only guards browser unload; dataset metadata can unmount on local-tab changes. Dashboard editing already has stronger route/unload/logout protection.

**User impact:** lost time and distrust, particularly after a long configuration process. A visible unsaved-changes message does not protect the work.

**Concrete improvement:** use a consistent dirty/busy model across editors. Intercept internal routes, local-view changes and logout; offer Stay/Discard and Save where valid. Preserve drafts through recoverable errors. Extend coverage to import configuration/metadata, where unguarded local state is a **code-inferred** risk, not an exercised loss case. Retain explicit publication and avoid automatic replay of uncertain saves.

**Acceptance:** repeat both reproduced journeys; edits must remain recoverable or require an explicit discard. Evidence anchors: `analytics/pages.tsx:51`, `datasets/pages.tsx:33,45,48`; compare `dashboards/pages.tsx:42–49`. Suggested command: `$impeccable harden`.

### 2. [P1 — Major] Charts shrink into unreadable miniatures inside dashboard widgets

**Evidence: current synthetic renders and DOM measurements; retained captures agree.** A 4/12 desktop widget rendered chart-label bounds around **5px high**; mobile analytical/dashboard labels were around **6px high**, although computed SVG CSS says 14px. The 900-unit SVG scales the labels with the drawing. One desktop widget exposed **353px** of a **1,008px**-high body. Source/method paragraphs precede the graph; exact tables require more vertical and horizontal scrolling.

**User impact:** users cannot scan and compare results without entering several independent scroll areas. The dashboard's main job is impaired even though exact numbers remain available.

**Concrete improvement:** introduce a compact widget result view: chart/KPI first, short source/version line, and explicit Exact values/Method details. Make chart geometry respond to its actual container; preserve readable text instead of shrinking a complete desktop graphic. Provide expand-to-inspect. On phones, allow a deliberate scrollable plot or adapted chart layout. Keep exact values, missingness and keyboard-accessible tables.

**Acceptance:** the same small widget and phone viewport must show readable labels and a meaningful comparison without opening multiple scroll regions. Anchors: `analytics.css:11–13`, `analytics/charts.tsx`, `dashboards/pages.tsx:97`, `dashboards.css:2–10`. Suggested commands: `$impeccable adapt`, `$impeccable layout`.

### 3. [P1 — Major] Analytical setup exposes too many decisions before the first useful result

**Evidence: current synthetic renders, retained import/analysis captures and code.** A modest grouped-mean analysis exposed **37 main controls**; its result page was **5,533px** high on desktop and **6,557px** on a 390px phone. Sources, filters, measures, grouping, chart appearance, templates, results and saving share a long vertical form. Import shows four step labels while all editor sections remain expanded. Useful templates appear after manual calculation configuration.

**User impact:** disproportionate effort for “show mean price by group,” repeated scrolling between inputs/result/save, and uncertainty about which fields are required now. The statistical capability is valuable; simultaneous exposure is the avoidable load.

**Concrete improvement:** structure Source → Question/calculation → Result → Save with a compact persistent source/version summary. Offer applicable pharmaceutical templates early alongside custom analysis. Progressively reveal advanced filters, extra measures, chart styling and conventions. Make import stages navigable, retaining a preview and validation summary. Do not remove immutable-version selection, explicit mappings or publication checks.

**Acceptance:** the simple grouped-mean journey has a clear next action and reaches a result without opening advanced chart styling. Anchors: `analytics/pages.tsx:79–87`, `analytics/controls.tsx`, `datasets/import.tsx:64–89`. Suggested commands: `$impeccable shape`, `$impeccable distill`.

### 4. [P2 — Minor] Assistant qualifications are hard to read, and mobile length errors are invisible

**Evidence: live public/local-draft checks and synthetic result renders.** Collection date, recorded-price labels, stock qualifications and expiry are largely **10–11px**; candidate package text reaches **10px** on mobile. The price is much more prominent. At 390px, entering **2,001 characters** set `aria-invalid=true` and disabled Send, but the “2001 / 2 000” element had `display:none`; visible help still described conversation expiry and there was no visible error message.

**User impact:** users can miss which package and observation date a price belongs to, or cannot understand why a long question will not send. These are observed presentation problems; actual clinical misuse was not studied.

**Concrete improvement:** increase package identity and essential qualifiers to a readable supporting-text scale; place observation date near recorded price and retain deeper source disclosure. Keep an invalid length count plus “Shorten your question by N characters” visible and announced at every breakpoint. Do not simply enable invalid submissions. Make send/reset controls more comfortable to tap; the enabled mobile Send target measured 35×35px.

**Acceptance:** package/date/stock context is readable on a phone; a pasted over-limit question explains the block and preserves the draft. Anchors: `chat.tsx:30,85,88`, `app.css:149,172–176`, `medication-card.tsx:12–20`. Suggested commands: `$impeccable typeset`, `$impeccable clarify`, `$impeccable harden`.

### 5. [P2 — Minor] Navigation and page hierarchy do not orient users around their work

**Evidence: live public screens, current synthetic protected screens and code.** Global navigation has no current-route treatment; seven analyst/eight admin destinations/actions wrap across the phone header. Dataset/admin local tabs do indicate selection, so the inconsistency is global, not universal. After SPA navigation, focus stayed on the header link. Platform route titles remain “Pharma Analyse.” The home repeats availability prose, and workspace source places profile management ahead of the data workflow.

**User impact:** users spend effort re-establishing location and finding the next useful task. Screen-reader consequences of the focus/title pattern remain an inference: no screen reader was exercised.

**Concrete improvement:** add a clear current location, route-specific titles and deliberate focus on route changes. Group primary work destinations separately from profile/admin/assistant access without hiding them. Orient the workspace around Import/Continue/Open recent analysis. Give introduction visitors a truthful, labeled example of CSV → result and clear analytics/assistant entry paths. Avoid inventing customers or evidence claims.

**Acceptance:** users can identify the current section and resume a dataset/analysis without scanning unrelated settings. Anchors: `accounts/pages.tsx:27–38,45–50,100–103`, `admin/pages.tsx:26`. Suggested commands: `$impeccable onboard`, `$impeccable layout`.

## Loading, empty, error and success coverage

- **Loading:** current platform text status and synthetic assistant waiting state were inspected. Preserve status announcements; reserve structural space where content replacement disrupts orientation. A skeleton is not automatically preferable for every request.
- **Empty:** dataset empty state offers import guidance; assistant gives three actionable examples. Preserve these. Empty advanced results were not all rendered.
- **Error:** synthetic dataset failure exposes recovery; synthetic assistant provider failure preserves retry/edit and avoids automatic replay. Fix hidden invalid-length guidance and bring field errors nearer their cause.
- **Success:** assistant result and source detail are clear at the main-answer level; platform metadata confirmation is too transient. Distinguish save success, recalculation success and publication success with persistent concise context.

## Cognitive load, emotional journey and persona checks

**Platform: high load** in analytical setup: five checklist weaknesses — chunking, hierarchy, one decision at a time, competing choices and progressive disclosure. Related controls are grouped and version context supports recognition. Counts above four are review prompts, not a rule that complex tools may expose only four choices: thirteen operations inside a closed select are less intrusive than thirteen simultaneous buttons. The strongest evidence is the expanded section structure and repeated distance between setup/result/save.

**Assistant: lower baseline load**, with bounded examples and presentation choices, but a distinct recovery problem when the mobile send control disables without visible explanation.

The projected platform journey starts reassuringly with privacy/validation, loses momentum in setup, weakens its result moment through miniature plots, and can end badly with draft loss. Assistant progression is clearer: example → clarification → package → price, with useful recovery; provenance needs more visual weight. This is an expert projection, not observed user research.

- **First-time analyst archetype:** many controls before a simple question is answered; labels and templates need to guide sequence, not merely explain features.
- **Power analyst archetype:** drafts and result visibility matter more than ornamental brand changes. Saved configurations and keyboard layout controls are valuable accelerators.
- **Low-vision/keyboard/mobile archetype:** microtype, scaled chart text, faint field boundaries and route focus deserve testing. Existing outlines, skip links and table alternatives help. Precise analyst personas remain open; these are evaluation lenses, not invented target-user research.

## Accessibility interpretation and limitations

The bounded axe scan found **zero reported violations in twelve settled public states**, with an assistant `aria-prohibited-attr` incomplete item requiring manual review. It did not cover all protected states and cannot establish compliance. Current keyboard evidence shows visible platform outlines and a composer focus-within treatment: the textarea does not have *no* focus indicator.

Small text is a readability problem even where measured text contrast passes. Smaller-than-44px targets are comfort concerns, not automatically WCAG AA failures: [WCAG 2.2 target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) uses a 24px criterion with exceptions. [Non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) applies to cues required to identify a control, not every decorative border. [Reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) allows two-dimensional data tables; improve their usability without incorrectly classifying all horizontal scrolling as a failure.

## Proposed direction for review

A **task-oriented analytical workspace with readable results**, plus a **clearer, more legible pharmacy assistant**. Sequence analytical work, preserve traceability and permission boundaries, make charts useful at their displayed size, and unify editing safety. Give the assistant strong package/date/recorded-price context and reliable recovery feedback. Palette or branding changes should follow this functional direction, not substitute for it. No direction or implementation has been approved by this critique.
